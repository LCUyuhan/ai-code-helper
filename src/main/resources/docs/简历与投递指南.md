# 简历与投递指南

## 一页简历的结构

1. 基本信息：姓名、电话、邮箱、GitHub 链接（可选）
2. 求职意向：岗位名称与城市
3. 专业技能：按熟练度分层，不堆名词
4. 项目经历：一到两个，占一半以上篇幅
5. 教育经历或实习经历：应届生写教育，有实习写实习
6. 其他：证书、开源、技术博客，有就写，没有不凑

## 项目描述怎么写

公式：背景 + 你负责的部分 + 技术方案 + 结果。

反例：

- 使用了 Spring Boot、MyBatis、Redis 开发了图库项目。

正例：

- 图片上传：改为客户端直传对象存储，后端只签发临时凭证，接口平均耗时从 800ms 降到 120ms。
- 权限控制：基于 Spring AOP 和自定义注解实现接口级权限校验，覆盖 12 个管理接口。

要求：

- 每条描述都要能回答“为什么这么做”
- 有数字写数字，没有数字写对比或范围
- 写“熟悉”或“了解”，不写“精通”
- 删掉与岗位无关的内容

## 技术栈怎么写

按熟练度分三层：

- 熟悉：能独立开发，能讲原理，例如 Java、Spring Boot、MySQL
- 会用：能完成功能，例如 Redis、MyBatis-Plus
- 了解：看过文档、做过 demo，例如 Kafka、Docker

面试官会从“熟悉”里挑问题，所以要确保这一层的每个词都能展开。

## 投递节奏

- 优先内推，其次公司官网，最后招聘平台
- 工作日周二到周四上午投递，回复率更高
- 每投十份记录一次：公司、岗位、时间、结果
- 一周没有回复可以礼貌跟进一次，不要反复打扰

## 常见错误

- 简历超过两页，重点被稀释
- 项目全是 CRUD，没有技术决策
- 把课程作业写成商业项目
- 技能列表写“精通 Java”，但答不出 HashMap 扩容
- 邮箱不专业、电话打不通

## 面试前检查

- 简历上的每个技术名词都能解释
- 项目里的每个数字都能追溯来源
- GitHub 链接能打开，README 完整可运行
- 自我介绍能在 90 秒内讲完

# 面试准备与答题框架

## 一、面试流程

1. 自我介绍，1-2 分钟
2. 项目深挖，10-20 分钟
3. 技术基础，20-30 分钟
4. 算法或手写代码，20-40 分钟
5. 反问环节，5 分钟

不同公司的顺序会变，但项目和技术基础一定会有。

## 二、自我介绍结构

- 我是谁：学校、专业、工作经验
- 我会什么：一到两个技术方向
- 我做过什么：一个最能打的项目
- 我为什么来：与岗位的匹配点

控制在 90 秒，不要背简历全文。

## 三、项目讲述框架

背景 → 目标 → 方案 → 难点 → 结果 → 反思。

常见追问：

- 这个项目解决什么问题？
- 为什么选这个技术方案，还考虑过什么？
- 最难的点是什么，怎么解决的？
- 如果流量涨十倍，哪里会先崩？
- 如果重做一次，你会改什么？

注意：

- 主动说出局限，比被问出来好
- 不要把所有功能讲一遍，挑两个深入
- 数字要真实，能被继续追问

## 四、技术题答题结构

结论 → 原理 → 实践 → 边界。

以 HashMap 为例：

- 结论：数组加链表加红黑树，默认容量 16，负载因子 0.75
- 原理：哈希扰动、下标计算、扩容 rehash
- 实践：为什么重写 equals 必须重写 hashCode
- 边界：并发场景改用 ConcurrentHashMap

先给结论能让面试官快速判断你会不会，再展开细节。

## 五、不会的问题怎么答

- 不要沉默，不要编造
- 说出思路：我没有在生产环境用过，但我的理解是……可以再确认
- 把问题拆小，回答你确定的部分
- 面试后查清楚，下次能答

## 六、高频方向清单

- Java：集合、String、异常、泛型、反射
- 并发：线程池、锁、JMM、ConcurrentHashMap
- JVM：内存结构、GC、类加载、调优入门
- MySQL：索引、事务、锁、explain
- Redis：数据结构、持久化、缓存三大问题
- Spring：IoC、AOP、事务传播、Bean 生命周期
- 网络：TCP 三次握手、HTTP 与 HTTPS、跨域
- 项目：架构、难点、优化、复盘

## 七、反问环节

问团队和业务，不问薪资福利：

- 团队目前的技术栈和分工？
- 新人入职后前三个月的目标？
- 这个岗位最看重的能力是什么？

## 八、面试后的复盘

- 记录被问住的问题
- 24 小时内补齐答案
- 同一类问题连续两次答不好，说明是知识盲区
